1. Lab : les Primitive Types in Patterns, instanceof, and switch

Jusqu’à présent, le pattern matching et l’opérateur instanceof ne s’appliquaient qu’aux types objets, tandis que l’instruction switch ne prenait en charge les types primitifs que de manière partielle.

Le but de cette évolution est d’améliorer le pattern matching en autorisant les types primitifs dans tous les contextes de pattern, et étendre instanceof ainsi que switch pour fonctionner avec tous les types primitifs.

Le pattern matching avec instanceof et switch sont abordés dans les labs :

  • Le Pattern Matching for instanceof

  • Le Pattern Matching for switch

Avant de continuer, il est recommandé d’être familier avec ces sujets ou d’avoir préalablement réalisé les labs ci-dessus.

1.1. Le pattern matching avec instanceof

Jusque-là réservée aux types objets, l’opérateur instanceof est désormais applicable aux types primitifs. Si la valeur à gauche peut être convertie exactement en le type à droite, alors il est sûr de la caster vers ce type, et instanceof renvoie true. La conversion est dite exacte s’il n’y a pas de perte d’information lors de la transformation.

Par exemple, int 10 peut être converti vers un byte, mais pas int 128.

  • Certaines conversions sont toujours vraies et cela est déterminé dès le moment de la compilation : byte vers int, int vers long, float vers double…​

  • Les autres sont évaluées à l’exécution, comme long vers int par exemple, dont le résultat dépend de la valeur du long impliqué.

1.1.1. L’opérateur instanceof avec les entiers

Lorsque seuls des nombres entiers sont impliqués, la conversion est exacte si l’on a égalité avec == vers le type casté.

Par exemple, 128 instanceof byte renvoie false car 128 != (byte) 128.

{kb}
Dans la classe fr.sciam.workshop.javase.primitivepattern.MainPrimitivePattern, compléter la méthode verifierLongAvecInstanceof() afin de tester si le paramètre de type long peut être converti en byte, short, char ou en int de manière sûre avec instanceof. Afficher un message et la valeur dans chacun des cas.

  private static void verifierLongAvecInstanceof(long valeur) {
    if (valeur instanceof byte b) {
      System.out.println(b + " est un byte");
    }
    if (valeur instanceof char c) {
      // On cast en int pour afficher la valeur numérique et non le caractère
      System.out.println((int) c + " est un char");
    }
    if (valeur instanceof short s) {
      System.out.println(s + " est un short");
    }
    if (valeur instanceof int i) {
      System.out.println(i + " est un int");
    }
  }

1.1.2. L’opérateur instanceof avec les flottants

Lorsqu’un flottant est impliqué, la conversion est exacte si l’on a équivalence dans la représentation (au sens de la norme IEEE 754), résultat qui peut être obtenu avec Double::compare ou Double::doubleToLongBits par exemple.

{kb}
Compléter la méthode verifierDoubleAvecInstanceof() afin de tester si le paramètre de type double peut être converti en long, int ou en float de manière sûre avec instanceof. Afficher un message et la valeur dans chacun des cas.

  private static void verifierDoubleAvecInstanceof(double valeur) {
    if (valeur instanceof long l) {
      System.out.println(l + " est un long");
    }
    if (valeur instanceof int i) {
      System.out.println(i + " est un int");
    }
    if (valeur instanceof float f) {
      System.out.println(f + " est un float");
    }
    if (valeur instanceof double d) {
      System.out.println(d + " est un double");
    }
  }

1.2. Les types primitifs avec l’instruction switch

Il est désormais possible d’utiliser switch avec long, float, double, et boolean ainsi que leurs wrappers correspondants. Deux restrictions s’imposent néanmoins :

  • Si l’expression dans le switch est de l’un de ces types, alors les constantes des case doivent être du même type, ou du wrapper correspondant. Par exemple, si l’expression est de type float ou Float, les valeurs des case doivent aussi être des float.

  • Le switch doit être exhaustif, soit avec un default, soit avec un primitive type pattern englobant tel que case float f.

{kb}
Compléter la méthode verifierFlottantAvecSwitch() afin de tester si le float passé en paramètre :

  • vaut 0f

  • vaut PI 3.14f

  • vaut le nombre d’or 1.618f

  • ou bien est une autre valeur

Pour chaque cas, afficher un message dans la console.

  private static void verifierFlottantAvecSwitch(float valeur) {
    System.out.print("Test de " + valeur + " : ");
    switch (valeur) {
      case 0f -> System.out.println("zéro");
      case 3.14f -> System.out.println("PI");
      case 1.618f -> System.out.println("le nombre d'or");
      default -> System.out.println("autre flottant");
    }
  }

La possibilité d’appliquer une clause when (guarded case label) sur un case est valide, en respectant la dominance des patterns.

{kb}
Compléter la méthode switchFlottant() afin de tester également les cas suivants pour le float passé en paramètre :

  • est un entier

  • est un flottant négatif

  private static void verifierFlottantAvecSwitch(float valeur) {
    System.out.print("Test de " + valeur + " : ");
    switch (valeur) {
      case 0f -> System.out.println("zéro");
      case 3.14f -> System.out.println("PI");
      case 1.618f -> System.out.println("le nombre d'or");
      case int _ -> System.out.println("nombre entier");
      case float f when f < 0 -> System.out.println("flottant négatif");
      default -> System.out.println("autre flottant");
    }
  }
