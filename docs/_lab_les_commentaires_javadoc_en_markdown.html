1. Lab : les commentaires JavaDoc en Markdown

La possibilité de documenter du code Java avec des commentaires exploités par l’outil javadoc pour générer une documentation en HTML est présente depuis Java 1.0. Le JDK lui-même propose une documentation générée avec JavaDoc.

Les fonctionnalités proposées ont évolué au fur et à mesure de certaines versions de Java, mais le langage de balisage utilisé pour le formatage a toujours été HTML.

Les commentaires de documentation utilisent des délimiteurs particuliers : ils débutent par /** et finissent par */. Ces commentaires peuvent historiquement contenir :

  • du texte,

  • des tags HTML pour formater le contenu,

  • des tags JavaDoc pour fournir des méta-données sous la forme @xxx, exemple @param, @return, @throws, @since, @author, ⋯

C’était sans aucun doute un bon choix d’utiliser HTML en 1995, mais de nos jours, Markdown est beaucoup plus populaire que HTML pour la rédaction de documentation.

Le but de la JEP 467 est de permettre aux commentaires de la documentation JavaDoc de pouvoir aussi être écrits en Markdown. Cela facilite la lecture et la rédaction des commentaires de documentation du code et améliore l’expérience des développeurs Java dans ces tâches.

JDK

Standard en Java 23

JEP

467: Markdown Documentation Comments

Pour maintenir la compatibilité avec la forme historique, l’utilisation de Markdown requiert que chaque ligne de commentaire de documentation débute par un triple slash /// et soit placé à un endroit où un commentaire JavaDoc historique serait pris en charge, donc en tant que prologue d’un élément à documenter.

La syntaxe Markdown utilisée est la variante CommonMark, avec des améliorations pour prendre en charge la liaison avec des éléments de programme et les tableaux simples.

Le formatage du texte utilise la syntaxe Markdown. Un saut de paragraphe est indiqué avec une ligne blanche ou un caractère \ à la fin de la ligne.

la syntaxe Markdown n’est pas reconnue dans les tags HTML

Les balises JavaDoc tels que @param et @return restent inchangées et peuvent toujours être utilisées dans les commentaires de documentation en Markdown, ce qui garantit que les fonctionnalités JavaDoc existantes sont toujours utilisables surtout lorsqu’elles n’ont pas d’équivalent en Markdown.

{kb}
Compléter le commentaire de documentation de la méthode saluer() en ajoutant les tags JavaDoc @param, @throws et @see.

  /// @param prenom le prénom à utiliser
  /// @throws Exception en cas de soucis
  /// @see java.lang.System#out

Regénérer la documentation JavaDoc et rafraîchir la page de la documentation de la classe MaClasse.

les balises JavaDoc ne sont pas évaluées si elles sont utilisées dans du code ou des blocs de code.

L’utilisation de Markdown rend l’écriture et la lecture des commentaires de documentation JavaDoc plus facile comme le montrent les exemples ci-dessus.

Le résultat généré par l’outil javadoc est très similaire à la version équivalente utilisant la syntaxe historique de JavaDoc.
