1. Lab : les Flexible Constructor Bodies

Historiquement, afin de garantir l’initialisation des champs, la première instruction d’un constructeur doit obligatoirement être l’invocation d’un constructeur de la classe ou super-classe, explicitement en invoquant this() ou super() avec éventuellement des paramètres selon la surcharge du constructeur invoqué ou à défaut implicitement par le compilateur. Dans ce dernier cas, c’est le constructeur par défaut (sans paramètre) qui est invoqué.

C’est parfois contraignant, notamment car cela impose d’invoquer un autre constructeur, par exemple avant de pouvoir faire des contrôles sur les valeurs.

{kb}
Consulter la classe fr.sciam.workshop.javase.flexibleconstructor.EntierPositif et particulièrement son constructeur.

class EntierPositif extends Entier {

  public EntierPositif(int valeur) {
    super(valeur);
    if (valeur < 0) throw new IllegalArgumentException("La valeur est negative"); (1)
  }
}
1 Avant Java 22, le contrôle de la valeur doit se faire obligatoirement après l’invocation du super constructeur.

Exécuter la classe fr.sciam.workshop.javase.flexibleconstructor.MainBeforeSuper et vérifier qu’elle affiche dans la console :

Invocation constructeur Entier
java.lang.IllegalArgumentException: La valeur est negative
	at fr.sciam.workshop.javase.flexibleconstructor.EntierPositif.<init>(FlexibleConstructorBodies.java:17)

À partir de Java 22, il est possible d’avoir dans les constructeurs des traitements qui ne font pas référence à l’instance avant l’invocation explicite du constructeur dans une portion de texte dénommée prologue dans les spécifications.

Modifier la classe EntierPositif pour effectuer le contrôle de la valeur avant l’invocation du super constructeur.

class EntierPositif extends Entier {

  public EntierPositif(int valeur) {
    if (valeur < 0) throw new IllegalArgumentException("La valeur est negative");
    super(valeur);
  }
}

Exécuter la classe FlexibleConstructorBodies et vérifier qu’elle affiche dans la console :

java.lang.IllegalArgumentException: La valeur est negative
	at fr.sciam.workshop.javase.flexibleconstructor.EntierPositif.<init>(FlexibleConstructorBodies.java:16)

Constater que le super constructeur n’est plus invoqué.

Il n’est pas possible d’utiliser de référence à un membre de l’instance ou de sa super classe : il est donc impossible d’utiliser this.xxx ou super.xxx explicitement ou implicitement.

{kb}
Modifier la classe EntierPositif pour afficher la propriété héritée valeur avant l’invocation du super constructeur.

class EntierPositif extends Entier {

  public EntierPositif(int valeur) {
    System.out.println(this.valeur);
    if (valeur < 0) throw new IllegalArgumentException("La valeur est negative");
    super(valeur);
  }
}

Compiler la classe FlexibleConstructorBodies et constater qu’une erreur est émise :

    System.out.println(this.valeur);
                       ^

Déplacer l’affichage du champ valeur après l’appel au super constructeur. Compiler la classe FlexibleConstructorBodies et vérifier que cela fonctionne avec succès.

Il est néanmoins possible d’affecter une valeur à un champ non initialisé de la classe avant l’appel au super constructeur.

{kb}
Modifier la classe EntierPositif pour ajouter un champ non initialisé private final boolean debug puis lui affecter la valeur true dans le constructeur avant l’appel au super constructeur. Conditionner l’affichage du champ valeur à la valeur de ce booléen.

class EntierPositif extends Entier {

  private final boolean debug;

  public EntierPositif(int valeur) {
    this.debug = true;
    if (valeur < 0) throw new IllegalArgumentException("La valeur est negative");
    super(valeur);
    if (this.debug) {
      System.out.println(this.valeur);
    }
  }
}

Modifier la méthode main() en fournissant la valeur 7 au constructeur de EntierPositif.

EntierPositif entier = new EntierPositif(7);
